# B16. Сглаживание: MSAA 4× против FXAA против обоих

**Сравнивали.** Весь кадр карты на GPU (timestamp-query от начала первого прохода до конца последнего) в четырёх вариантах:
- без сглаживания (настройки по умолчанию, как в Swift);
- MSAA 4× (`settings.msaa()`): мировой проход в четырёх сэмплах с resolve;
- FXAA (`settings.fxaa()`): мировой проход в отдельную текстуру и полноэкранный проход FXAA в холст (перенос `FXAA.metal`);
- MSAA 4× и FXAA вместе.

Вид: нижний Манхэттен с камеры README эталона (z15.01, наклон 50°), локальный архив фикстур (без сети), со зданиями, тенями и деревьями. Каждый вариант это своя карта (число сэмплов пересоздаёт рендер): она дожидается всех тайлов, затем рисует кадр за кадром. Код: `apps/playground/src/bench/antialias.ts`, страница `bench-antialias`, `?only=<вариант>` оставляет один вариант для снимка.

**Окружение.** Mac пользователя, Chrome 157 headless, холст 1200×860 (1 пиксель на точку). 300 кадров на вариант после 20 прогревочных, два прогона. Частота GPU в headless заметно гуляет между прогонами, поэтому сравнивается p95 внутри одного прогона.

| вариант | GPU медиана, мс (прогон 1 / 2) | GPU p95, мс (прогон 1 / 2) |
|---|---|---|
| без сглаживания | 6.151 / 6.236 | 6.315 / 6.339 |
| MSAA 4× | 5.791 / 7.228 | 7.284 / 7.408 |
| FXAA | 6.321 / 6.319 | 6.429 / 6.437 |
| MSAA 4× + FXAA | 7.288 / 7.289 | 7.422 / 7.412 |

Сырые данные: `raw/bench-antialias-2026-11-21-20-55.json`, `raw/bench-antialias-2026-11-21-20-56.json` (и более шумный первый прогон `raw/bench-antialias-2026-11-21-20-54.json`).

**На глаз.** Вырезки 560×420 одного и того же места (край One World Trade Center, 2 пикселя на точку): `raw/b16/manhattan-none.png`, `manhattan-msaa_1.png`, `manhattan-fxaa_1.png`, `manhattan-msaa_1_fxaa_1.png`. При 2 пикселях на точку разница едва видна: без сглаживания на вертикальных и наклонных силуэтах зданий заметны одиночные ступеньки, MSAA убирает их чище всех, FXAA сглаживает те же края почти так же, слегка размывая тонкие линии дорог. Подписи рисуются в оверлее после FXAA и им не затрагиваются. MSAA вместе с FXAA на вид не отличается от одного MSAA.

**Решение: по умолчанию без сглаживания, как в Swift. MSAA 4× и FXAA остаются настройками.**
- Разница на экранах с 2 пикселями на точку почти не видна, а MSAA стоит около 1 мс GPU (16% кадра), что на облёте Манхэттена вывело бы p95 за бюджет 8 мс.
- FXAA почти бесплатен (около 0.1 мс при 1200×860) и сглаживает те же края: его стоит советовать для экранов с 1 пикселем на точку.
- Оба вместе не дают ничего сверх MSAA и стоят как MSAA: это сочетание не советуется, но и не запрещено.
- Правило «проигравший удаляется» здесь не применено к самим режимам: `fxaaEnabled` и `multisampleCount` это публичные настройки Swift API (`PostProcessingSettings`, модификаторы `.fxaa`, `.msaa`), их перенос входит в паритет API. Решение замера касается значения по умолчанию.
