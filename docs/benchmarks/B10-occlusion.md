# B10. Затенение долин (terrain occlusion)

**Сравнивали.** Затенение неба рельефом для 27 тайлов Mapterhorn из фикстур (Церматт z10–12, Terrarium в WebP, 512×512) с ключом стиля по умолчанию: радиус 3000 м, 8 направлений, сетка 128×128. Алгоритм один и тот же (перенос Swift `GroundReliefOcclusion.compute`: для каждой точки сетки среднее по направлениям синуса угла горизонта до радиуса), в двух вариантах:
- **CPU:** перенос на Rust в Wasm (`crates/bench-wasm/src/occlusion.rs`) в воркере, как его запускали бы тайловые воркеры движка. Полный путь: половинки высот копируются из JS в Wasm, байты затенения выходят обратно в `Uint8Array`. Отдельная строка: половинки уже лежат в Wasm после декодирования (расчёт рядом с декодером, без копирования внутрь).
- **GPU:** compute-шейдер WebGPU (`tile/relief/store/ground-relief-occlusion-gpu.wgsl`) по текстуре высот `r16float`, которую рельеф и так загружает для отрисовки (загрузка не входит в замер). Шейдер пишет байты в storage buffer со строками, выровненными до 256 байт, затем копирование в текстуру `r8unorm`. Лучи (смещения в текселях и обратные метры шага) строятся на CPU во f32 так же, как в Swift. Замер включает создание буферов, кодирование, отправку и завершение: время на стене до `onSubmittedWorkDone`, доля главного потока (кодирование и `submit`) и время прохода на GPU по `timestamp-query`.

Точность: байты GPU сравниваются с байтами CPU для всех 27 тайлов. Код: `apps/playground/src/bench/occlusion*.ts`, страница `bench-occlusion` (`node scripts/bench.mjs bench-occlusion`).

**Окружение.** Mac пользователя: Apple M2, 8 ГБ, macOS 26.5. Chrome 157.0.8103.79 headless (Playwright, системный Chrome), cross-origin isolation. 5 прогревочных проходов по набору, затем 50 и 100 проходов (1350 и 2700 замеров на вариант), варианты CPU чередуются.

| путь | мс на тайл (медиана, 50 / 100 проходов) | p95 |
|---|---|---|
| CPU: Wasm в воркере, половинки копируются внутрь, байты наружу | 3.210 / 3.215 | 3.590 / 3.605 |
| CPU: Wasm в воркере, половинки уже в Wasm после декодирования | 3.185 / 3.190 | 3.570 / 3.580 |
| GPU: от кодирования до `onSubmittedWorkDone` (стена) | 0.465 / 0.465 | 0.490 / 0.485 |
| GPU: главный поток, кодирование и `submit` | 0.020 / 0.020 | 0.025 / 0.025 |
| **GPU: проход на GPU (`timestamp-query`)** | **0.213 / 0.134** | **0.387 / 0.386** |

Байты GPU и CPU совпадают полностью: наибольшая разница 0, отличий 0 из 442 368.

Сырые данные: `raw/bench-occlusion-2026-11-21-21-25.json` и `raw/bench-occlusion-2026-11-21-21-26.json`.

**Решение: compute-шейдер на GPU.** Он в 15–25 раз быстрее по времени GPU и в 7 раз быстрее по времени до готовности. Время на стене (0.47 мс) почти целиком задержка очереди Chrome до `onSubmittedWorkDone`, сам проход занимает 0.13–0.21 мс.

Что учитывалось помимо цифр:
- CPU-вариант работает в воркере и не стоит кадру ничего, а GPU-вариант занимает очередь GPU главного потока. Бюджет кадра 8 мс p95 для CPU и GPU. Один тайл стоит 0.13–0.39 мс GPU, то есть 2–5% бюджета, и 0.02 мс главного потока. При смене ключа (ползунок радиуса в панели) пересчитываются все резидентные тайлы: 30 тайлов это около 4–12 мс GPU, поэтому пересчёт нужно раскладывать по кадрам (несколько тайлов за кадр), как Swift раскладывает его по очереди.
- CPU-вариант не бесплатен и в воркере: 3.2 мс на тайл занимают тот же воркер, что разбирает векторные тайлы, и задерживают появление тайла рельефа. Пересчёт 30 тайлов при смене ключа это около 100 мс работы воркеров плюс пересылка половинок высот из главного потока обратно в воркеры.
- GPU-вариант проще для движка: ему нужна только текстура высот, которая уже есть, а результат сразу текстура `r8unorm`, без загрузки байтов из воркера.

Применено: модуль `packages/immersive-map/src/tile/relief/store/ground-relief-occlusion-gpu.ts` (класс `GroundReliefOcclusionGpu`, `compute(heights, tile, key)` возвращает текстуру `r8unorm` resolution², есть и `encode` в чужой энкодер кадра). Воркеры возвращают только высоты, без затенения. Перенос на Rust для CPU остался только в `crates/bench-wasm` как вариант бенчмарка и эталон, с которым сверяются байты шейдера.
